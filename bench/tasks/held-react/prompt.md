Write a React 19 component in plain JavaScript (JSX, no TypeScript) for our article editor: a tag input. Put it in `src/TagInput.jsx`, default-exporting `TagInput({ initialTags = [], maxTags = 5, onChange })` where `initialTags` is an array of strings used on the first render only and `onChange`, optional, is called with the new array of tags after each add or remove, never after a rejected entry. List `react` and `react-dom` in `package.json`.

It shows the tags as `<li>` elements, in order, in a `<ul aria-label="Tags">`, each `<li>` holding the tag's text and a `<button type="button" aria-label="Remove react">` (with the tag's text) that removes it; with no tags there is no `<ul>`. Then an `<input aria-label="Add tag">`. On `keydown` of Enter in the input, its text is trimmed and added as the last tag, and the input is cleared; the Enter is prevented (`preventDefault`) so it never submits a form. A blank or whitespace-only entry is ignored. An entry longer than 20 characters is rejected with `<p role="alert">Tags are at most 20 characters</p>`, one that matches a tag in any letter case with `<p role="alert">Tag already added</p>`; a rejected entry stays in the input, and the alert disappears when the input text changes or a tag is added or removed. On `keydown` of Backspace in an empty input, the last tag is removed. While there are `maxTags` tags or more, the input has the `disabled` attribute.
