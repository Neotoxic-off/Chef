# Changelog

## 1.4.0 (2026-11-20)

Lean rules, and a benchmark that covers the most-used stacks.

- Skill: `lean.md`, adapted from ponytail (MIT): the smallest complete change, and short replies and agent reports.
- Benchmark harness: `run.sh` resumes a batch (`RESUME=1`) and stops at a dollar cap (`MAX_TOTAL_USD`); timeouts kill the whole process tree; runs that could not be scored are left out of the correct rate; a shared `scorer_lib.py`; every scorer is tested in CI on a known-good and a known-bad answer, with a weekly strict run of the Docker fixtures; `scripts/check_references.py` checks the version line, links and code blocks of all 127 references.
- Nine new tasks for the most-used stacks: Node, React, Bash, SQL, PHP, PowerShell, C, C++, Kotlin. 3 runs each: chef 1.4's first answer is accepted 67% of the time (plain Claude: 44%), 0.37 fix rounds per task (0.74), $0.260 per task with fixes ($0.150); every chef first answer passes its hidden test, plain Claude fails 2 of 27. With 3 runs per stack, read the total, not a single stack.
- Results, 39 runs on the 13 tasks, reviewed with the 1.2 loop: chef 1.4's first answer is accepted 92% of the time (1.3: 90%, plain Claude: 59%), 0.10 fix rounds per task (0.13, 0.46), $0.185 per task with fixes (1.54x plain Claude). 1.3 and 1.4 differ by one review out of 39: read them as equal.
- Version chart: chef 1.4 on the Python, Docker and Prometheus tasks: 9 of 9 merged as is, $0.173 per task, 47 s median first answer.

## 1.3.0 (2026-11-20)

A benchmark-and-honesty release, decided by a council on the 1.2 results: no new code rules.

- Skill: an explicit instruction in the prompt wins over chef's conventions and `.chef.md`, never over security or the project folder; an unclear request gets one question to the user before the council; free RAM and CPU are checked once per session; repeated text removed from `SKILL.md`.
- References: the 90 references the benchmark does not cover say "Written for <versions>, not benchmarked" instead of "Verified against".
- Benchmark harness: a run that ends on an API error or usage limit is refused everywhere (`score.py check`, `run.sh`, merge loop, reviews) instead of counted; `merge.json` and the history point are generated by the scripts and name the harness commit and reviewer id; a review counts as merged only when it lists no blocker or major change; the Prometheus seed serves the `/metrics` its prompt describes; 6 scorers are tested in CI on a known-good and a known-bad answer.
- Results, 39 runs on the 13 tasks, reviewed with the 1.2 loop so every arm shares one reviewer: chef 1.3's first answer is accepted 90% of the time (1.2: 87%, plain Claude: 59%), 0.13 fix rounds per task (0.15, 0.46), $0.181 per task with fixes (1.51x plain Claude). 1.3 changed no code rule: 1.2 and 1.3 differ by one or two reviews out of 39.
- Version chart: chef 1.3 on the Python, Docker and Prometheus tasks, 3 runs each, reviewed like the earlier versions: 9 of 9 merged as is (1.2: 8 of 9), $0.169 per task (1.2: $0.156), 41 s median first answer. One review per step: read it as noise, not as a gain.
- README: who gains (teams with a reviewer), lines the reviewer reads (98 without chef, 231 with), the version chart read as a trend, a break-even chart, and how to turn chef off in one project.

## 1.2.0 (2026-11-20)

- Fewer wasted turns, from a council review of the 1.1 traces: files are created with the Write tool, never shell heredocs; a filtered check keeps its exit code (`set -o pipefail`); nothing is written outside the project folder; a refactor is proven first by characterization tests kept in the repo.
- References checked on the real tools: C# test projects for xUnit v3, Rust tests without `expect` and no `-A` on the command line, hadolint from stdin, `depends_on: service_healthy` only for startup dependencies, Go `-race` only with cgo, Python test ignores and parsed-input checks, and a TypeScript CLI's `bin` file starts with `#!/usr/bin/env node`.
- Benchmark: the reviewer copy follows `.gitignore` (no `node_modules` or `dist`), the merge loop records reviewer cost and lines to review, and three harder tasks (Python streaming import, TypeScript retry with backoff, Go cursor pagination) with hidden tests. Their scorers accept streaming reads in blocks of up to 2 MiB and a changed store query method in Go.
- Results, 39 runs per arm, every arm reviewed again with the new copy: chef 1.2's first answer is accepted 87% of the time (chef 1.1: 85%, plain Claude: 59%), with 0.15 fix rounds per task (0.23, 0.46), at 1.62× plain Claude's cost once its fixes are counted. 1.2 is not measurably better than 1.1; the three harder tasks do not separate the arms yet.

## 1.1.0 (2026-11-20)

- Fixes from the blind reviewers' reasons in the 1.0 benchmark: the task's stated contract (exception types, exit codes, formats) wins over conventions; tests assert the exact exception or exit code; never invent data to signal an error; error messages say what and where; a refactor keeps behavior, fallbacks and supported runtimes exactly; input size is bounded before expensive parsing.
- Docker: apps that ignore SIGTERM do not run as PID 1 (`init: true` or `tini`), memory and CPU limits, log rotation, only digests read from the registry.
- Less scaffolding on small tasks: tool configs in the project's main config file, CI, coverage gates and mutation testing only when the project has them or the user asks; every configured tool declared as a dev dependency (`pytest-cov` with `--cov`).
- Benchmark: cost to mergeable. A blind reviewer sends its required changes back until it would merge (`bench/merge_loop.py`). Chef 1.1 is accepted the first time in 87% of tasks against 56% for plain Claude, needs 70% fewer review rounds, and costs 1.45x plain Claude once plain Claude's fixes are counted (2.2x for the first answer alone).
- README cut to the essentials; benchmark details in `bench/README.md`; version history chart.

## 1.0.0 (2026-11-20)

Stable release. The public contract under semantic versioning: the commands (`/chef:chef`, `/chef:level`, `/chef:status`, `/chef:transform`), the levels (`lite`, `full`, `max`), the `.chef.md` keys, the agent names, the hook behaviour, and `export/AGENTS.md`.

- `SKILL.md` opens with 12 core rules, then an inline index of the common stack references (one read less before the first edit), then the detailed house rules.
- Types follow each language's idiom: every signature and public field typed, locals as the language expects (`:=` in Go, `var` in C# and Java, `let` in Rust when the type is obvious). References, reviewer, senior and transform updated to match.
- `export/AGENTS.md`: chef's core rules for any agent that reads `AGENTS.md` or `CLAUDE.md`. `scripts/check.sh` keeps it identical to the core of `SKILL.md`, and checks that `plugin.json` matches this file's version.
- Agents receive the skill's path in their brief instead of searching the disk for it.
- Config comments in references no longer say "house rule", which leaked into generated code.
- Benchmark: 13 tasks across 11 stacks (Python, TypeScript, Go, Rust, C#, Java, Docker, Prometheus, Terraform, Helm, GitHub Actions, plus a bug fix and a refactor), a control arm (the core rules in a `CLAUDE.md`), blind pairwise judging in both orders, task-level sign test and bootstrap interval, results in `bench/results/summary.json` and charts generated from it.
- Results: every arm passes every correctness check; blind reviewers prefer chef on 12 of 13 tasks against plain Claude and against the control (p = 0.0005), would merge its code as is 88% of the time against 47% and 56%; chef costs about 2.4× plain Claude.

## 0.8.0 (2026-11-19)

- Levels `lite | full | max`, set with `/chef:level`. `full` stays the default. `lite` keeps every code rule but drops the council and the reviewer; `max` runs both on every non-trivial change.
- Per-project `.chef.md`: level, strict mode, coverage target, council, and a `## Decisions` list so an answered question is not asked again.
- `/chef:status`: active level, overrides, detected stacks, and the session's tokens, subagents and elapsed time.
- Stop hook `pin-gate.sh`: blocks once when a changed GitHub workflow uses an action not pinned by a full commit SHA.
- Transform stop gate: once a batch is `[x]`, `TRANSFORM.md` needs `Target:` and `## Council`, and every ticked batch needs its own commit.
- "Talk less" tightened: about 10 lines per reply, result first, closing line on what was skipped and the risk.
- Benchmark rerun with real checks: hidden tests, coverage, `mypy --strict`, `tsc --strict`, hadolint.

## 0.7.0 (2026-11-19)

- `/chef:transform <goal>`: upgrades and migrations in the AWS Transform style. Baseline, plan in a committed `TRANSFORM.md`, council review, user approval, then batches that are validated, reviewed and committed one by one, with resume and a before/after report.
- Migration mode: the diff holds only what the migration needs; chef's style rules apply to new and changed lines only.
- Stop hook scoped to the transform skill: blocks the end of a turn once while a batch is marked `[~]`. Not active outside a transform.
- 5 recipes: `dotnet-upgrade.md`, `ts-strict.md`, `test-coverage.md`, `java-upgrade.md`, `python-upgrade.md`.
- A new project goes through the council before its first file.
- CI: `scripts/check.sh` checks every skill's frontmatter; bats tests for the stop hook.
