# F#

Written for .NET SDK 10.0.401, FSharp.Core 11.0.101 on NuGet, Fantomas 8.1.2, FSharpLint 0.27.2, xUnit v3 (Nov 2026), not benchmarked. Current versions: `dotnet --list-sdks`, `dotnet package search <id>` or nuget.org. Shared .NET rules (central package versions, MTP, coverage): see `csharp.md`.

## Project settings (`Directory.Build.props`)

```xml
<Project>
  <PropertyGroup>
    <TreatWarningsAsErrors>true</TreatWarningsAsErrors>
    <WarnOn>1182,3390</WarnOn>
    <Nullable>enable</Nullable>
  </PropertyGroup>
</Project>
```

`1182` reports unused variables, `3390` checks XML doc comments. Both are off by default. Set `WarnOn` once, comma-separated: only its last occurrence counts.

## Lint and format: Fantomas + FSharpLint

- Install both as local tools (`dotnet new tool-manifest`, `dotnet tool install fantomas`, `dotnet tool install dotnet-fsharplint`).
- Format: `dotnet fantomas .`; CI runs `dotnet fantomas --check .` (exit code 99 when a file needs formatting).
- Lint: `dotnet fsharplint lint App.sln` (or a `.fsproj`). It exits non-zero on any warning. Its default rules accept type annotations everywhere and double-backtick test names (checked).
- Known issue (checked): on an xUnit v3 test project, FSharpLint also lints the generated `obj/.../XunitAutoGeneratedEntryPoint.fs` and reports FL0042 on its module name. That is generated code you cannot fix: tell the user; do not add it to `ignoreFiles` on your own.

## Code

- Explicit types on public functions (parameters and return) and values; let inference type local bindings and lambdas:
  ```fsharp
  let withdraw (balance: decimal) (amount: decimal) : Result<decimal, WithdrawError> =
      if amount > balance then Error InsufficientFunds else Ok(balance - amount)

  let fees: decimal list = amounts |> List.map (fun (a: decimal) -> a * feeRate)
  ```
- Errors as values: `Result` and `Option`; discriminated unions for error cases. Use `TryParse` / `tryFind` instead of catching exceptions.
- Exceptions only around I/O you cannot check first; `use` for `IDisposable`.
- Records and unions are immutable by default; keep them so. No `mutable` outside tight local loops.
- Single-case unions or units of measure for domain values (`[<Measure>] type eur`).
- `task { }` for async I/O, pass a `CancellationToken`. No `Async.RunSynchronously` in a library.
- XML doc comments (`///`) only on a library's public API (see SKILL.md).

## Tests

- xUnit v3 on Microsoft.Testing.Platform (as in `csharp.md`). Test names use double backticks and state the behavior:
  ```fsharp
  [<Fact>]
  let ``withdraw with insufficient funds returns InsufficientFunds`` () : unit =
      let result: Result<decimal, WithdrawError> = withdraw smallBalance largeAmount
      Assert.Equal(Error InsufficientFunds, result)
  ```
- Property tests with FsCheck (`FsCheck.Xunit`) for pure logic and round-trips.
- Integration: `Testcontainers` for databases, `WebApplicationFactory<T>` for ASP.NET Core.
- Coverage: same tools and 90% gate as `csharp.md`.
- Mutation testing: Stryker.NET supports C# only. No maintained F# tool known (unverified).

Order before done: `dotnet fantomas .` then `dotnet build` then `dotnet fsharplint lint App.sln` then `dotnet test`.
