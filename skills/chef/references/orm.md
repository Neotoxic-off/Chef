# ORMs: EF Core, Prisma, SQLAlchemy, Hibernate

Builds on `sql.md`. Written in November 2026 (not benchmarked): EF Core 10.0.x, Prisma 7.10.x, SQLAlchemy 2.1.x, Hibernate ORM 7.4.x (8.0 in CR). Check each project's GitHub releases page before pinning.

## Rules for every ORM

- Look at the SQL it sends. Turn on SQL logging in dev and tests (without parameter values in shared logs: they may hold personal data).
- Load relations explicitly per use case. Lazy loading in a loop is N+1: one query per row.
- Read-only queries skip change tracking and select only the fields the caller needs.
- One unit of work per request or job: open, do the work, commit once. No long-lived sessions or contexts.
- Raw SQL only through the ORM's parameterized API. The "unsafe" or "raw string" variants never see user input.
- Schema changes go through the ORM's migration tool, reviewed by a human: autogenerate is a draft.
- Test against the real engine in Testcontainers, never an in-memory provider or SQLite standing in for Postgres.

## EF Core

- `AsNoTracking()` for reads; `Include`/`ThenInclude` for relations; `AsSplitQuery()` when several collection includes multiply rows.
- No lazy-loading proxies. Project to DTOs with `Select`.
- `FromSql($"... {id}")` and `ExecuteSql` turn interpolated values into parameters. `FromSqlRaw` with concatenation is an injection risk.
- Bulk changes: `ExecuteUpdateAsync` / `ExecuteDeleteAsync`, not load-modify-save loops.
- Migrations: `dotnet ef migrations add`, implement `Down()`, ship with `dotnet ef migrations bundle` or a script, not `Database.Migrate()` at app start on multiple instances.

```csharp
List<OrderDto> orders = await db.Orders
    .AsNoTracking()
    .Where((Order o) => o.CustomerId == customerId)
    .Select((Order o) => new OrderDto(o.Id, o.Total, o.Lines.Count))
    .ToListAsync(ct);
```

## Prisma

- Prisma 7: Rust-free client by default. Follow the official v7 upgrade guide for driver adapter setup.
- `select` or `include` explicitly; batch with `findMany({ where: { id: { in: ids } } })` instead of queries in a loop.
- `$queryRaw` and `$executeRaw` as tagged templates are parameterized. `$queryRawUnsafe` / `$executeRawUnsafe` never get user input.
- `prisma migrate dev` locally, `prisma migrate deploy` in CI/CD. Migrations have no down step: write the rollback SQL with `prisma migrate diff` and commit it next to the migration.
- `$transaction([...])` or the interactive form for multi-write units; keep them short.

## SQLAlchemy 2.x

- 2.0 style only: `select()`, `Session.execute`/`scalars`, typed `Mapped[...]` columns. No legacy `Query`.
- Eager load per query with `selectinload` (collections) or `joinedload` (many-to-one). Set `lazy="raise"` on relationships so accidental lazy loads fail loudly.
- `with Session(engine) as session, session.begin():` is the unit of work.
- `text("... WHERE id = :id")` with bound parameters; never f-strings in SQL.
- Alembic: review every autogenerated revision and write a working `downgrade()`.

```python
stmt: Select[tuple[Order]] = (
    select(Order).where(Order.customer_id == customer_id).options(selectinload(Order.lines))
)
orders: list[Order] = list(session.scalars(stmt))
```

## Hibernate / JPA

- `@ManyToOne` and `@OneToOne` are eager by default in JPA: always write `fetch = FetchType.LAZY`.
- Fetch what a use case needs with `join fetch` or an entity graph; set `hibernate.default_batch_fetch_size` as a safety net.
- Read-only work: `@Transactional(readOnly = true)` or `StatelessSession`. Projections to records for lists.
- Parameters with `setParameter`, never string-built JPQL or native SQL.
- Schema via Flyway or Liquibase; `hibernate.hbm2ddl.auto` is `validate` or `none` outside throwaway dev.
