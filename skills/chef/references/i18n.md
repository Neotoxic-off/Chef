# Internationalization (i18n) and localization

Checked November 2026 against BCP 47, Unicode CLDR, Unicode MessageFormat 2.0 (stable since CLDR 47) and the ECMAScript `Intl` and Temporal APIs.

## Strings

- No user-facing text in code. Every string goes through the project's i18n library (i18next, FormatJS/`react-intl`, gettext, ICU4J, .NET resources, Android/iOS string catalogs).
- Message IDs are stable keys that say what the text is for (`checkout.payButton`), not the English text.
- Never concatenate translated parts. Pass whole sentences with placeholders; translators need to reorder words.
- Plurals and gender through ICU MessageFormat (or MessageFormat 2 where the library supports it), never `count === 1 ? ... : ...`. CLDR plural categories differ per language (Arabic has six).

```
{count, plural,
  =0 {Your cart is empty.}
  one {You have # item in your cart.}
  other {You have # items in your cart.}
}
```

- Give translators context: a description per message and screenshots in the translation platform.
- CI fails on missing keys, unused keys, and placeholders that differ between the source and a translation.

## Locale

- Locales are BCP 47 tags (`fr-CA`, `zh-Hant-TW`). Negotiate from the user's setting, then `Accept-Language`, then a default, with a fallback chain (`fr-CA` then `fr` then the default).
- Format numbers, currencies, dates, lists and relative times with the locale-aware API (`Intl.NumberFormat`, `Intl.DateTimeFormat`, `Intl.ListFormat`, `Intl.RelativeTimeFormat`, ICU, `CultureInfo`). Never hand-build them.
- Sort and compare user-visible text with a collator (`Intl.Collator`), not code-point order.
- Parse user input with the same locale you display it in.

```ts
const priceFormatter: Intl.NumberFormat = new Intl.NumberFormat(locale, { style: "currency", currency: currencyCode });
const label: string = priceFormatter.format(amount);
```

## Time

- Store and transmit instants in UTC (RFC 3339). Store the user's IANA time zone (`Europe/Paris`), never a fixed offset.
- Convert to local time only at display. Schedules in local time ("9:00 every Monday") store the wall time plus the zone.
- JavaScript: Temporal where the runtime ships it (Chrome 144, Firefox 139, Node 26), a polyfill elsewhere; avoid new `Date` arithmetic.

## Text and layout

- UTF-8 everywhere: files, database (`utf8mb4` on MySQL), HTTP headers. Normalize user input to NFC before comparing or storing keys.
- Length limits count user-perceived characters (grapheme clusters, `Intl.Segmenter`), not bytes or UTF-16 code units.
- Right-to-left: set `dir` on `<html>`, use CSS logical properties (`margin-inline-start`, `inset-inline-end`), mirror direction icons. Use `dir="auto"` or `<bdi>` for user-generated text.
- Leave room: translations can be much longer than English. No fixed-width text containers.
- Set `<html lang>` to the active locale.

## Tests

- Pseudo-localization in CI or dev (accented, padded, bracketed strings) to catch hard-coded text, truncation and concatenation.
- Unit tests for formatting in at least one RTL locale and one locale with complex plurals: `cart summary in Arabic with 3 items uses the few plural form`.
- Visual tests of key screens in the longest supported language and in an RTL language.
